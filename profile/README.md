<h2>一、实验怎么设计</h2>
<p>控制变量是这类实验唯一的难点。机器不变、线路不变、时间段接近，只改隔离方式，结论才有意义。</p>

<h3>三组配置的定义</h3>
<p>A 组用系统级代理加日常主浏览器配置文件，是最省事的做法；B 组用独立浏览器配置文件加同一出口，隔离 Cookie 与本地存储；C 组在 B 的基础上把浏览器放进虚拟机或独立系统账户，连字体、插件、缓存路径都分开。三组依次跑，每组至少用满一天。</p>

<h3>四个观测指标</h3>
<p>一是首次登录是否要求额外验证；二是对话过程中断次数；三是切换账号后是否需要重新登录；四是页面加载完整度，是否有静态资源失败。前两项偏网络，后两项偏隔离。记录时写具体次数和时间点，不要只写「正常」或「有问题」。</p>

<h2>二、A 组：系统代理加主配置文件</h2>
<p>这组是大多数人的默认状态，作为基线。</p>

<h3>具体做法</h3>
<p>在系统设置里填代理地址与端口，浏览器不做任何隔离。此时所有标签页共享同一份 Cookie、localStorage 和 IndexedDB。用 <code>curl -s https://ipinfo.io/json</code> 确认出口，再在浏览器控制台确认时区与出口城市一致。运行一天，记录四项指标。</p>

<h3>预期会暴露的问题</h3>
<p>同一浏览器登录两个账号时，会话键值互相覆盖，表现为切换后要重新登录、或者看到上一个账号的残留状态。这不是 IP 的问题，是存储共享的问题。A 组的意义就在于把这个现象固定下来，作为后面两组的对照基线。</p>

<h2>三、B 组：独立配置文件加同城出口</h2>
<p>成本最低的隔离手段，多数场景够用。</p>

<h3>配置文件的创建与验证</h3>
<p>Chrome 地址栏输入 <code>chrome://version</code>，看「个人资料路径」，复制整个目录改名即可得到一份独立配置；也可以用命令行 <code>chrome.exe --user-data-dir="D:\profiles\p1"</code> 直接指定目录启动。验证方法是同时开两份配置，各自登录不同账号，看是否还会串号。</p>

<h3>代理绑定到单个配置文件</h3>
<p>Chrome 本身不支持按配置文件设代理，常见做法是给每个配置文件装一个代理扩展并单独配置，或者用两个不同的 PAC 文件配合启动参数。要避免的是「系统代理改了但扩展还在指旧地址」这种双层叠加，检查方式是关掉扩展后再看出口是否变化。</p>

<h2>四、C 组：虚拟机或独立系统账户</h2>
<p>隔离最彻底，代价是启动慢、占资源。</p>

<h3>隔离到什么程度</h3>
<p>虚拟机有独立的系统时区、字体列表、网卡和缓存目录，浏览器配置天然分开。独立系统账户介于两者之间，共享内核但用户目录分开，成本比虚拟机低。判断标准是：你在 A 组里遇到的串号现象，在 C 组是否完全消失。</p>

<h3>网络路径要单独确认</h3>
<p>虚拟机默认走 NAT，出口跟随宿主机；桥接模式则可能拿到另一个地址。实验期间建议用 NAT 并确认虚拟机内的出口与宿主一致：在虚拟机里跑一次 <code>curl -s https://ipinfo.io/json</code>，与宿主机的输出对比。两者不一致会让实验结果失去意义。</p>

<h2>五、结果对照与怎么选</h2>
<p>三组跑完，把四项指标并排看，结论通常很清晰。</p>

<h3>典型的对照结果</h3>
<p>A 组在「切换账号需重登」这一项上几乎必然失分；B 组能解决绝大部分串号问题，网络类指标与 A 组接近；C 组在隔离项上最好，但对话中断次数不降反升的情况也常见，因为虚拟机网络栈多了一层 NAT，延迟增加。如果主要痛点是串号，B 组足够；如果需要同时维护三个以上环境，才考虑 C。</p>

<h3>表格怎么读</h3>
<p>别只看总分，要看失分项落在哪一层。网络类指标（中断、加载失败）三组差异不大，说明瓶颈在线路；隔离类指标（重登、串号）差异明显，说明问题在配置。这个判断直接决定你该花钱升级线路，还是花十分钟建个配置文件。</p>

<h2>常见问答</h2>
<h3>实验需要跑多久才有参考价值？</h3>
<p>答：每组至少完整一天，包含一次早晚高峰。住宅线路的抖动集中在晚间，只跑白天的结论会偏乐观。三组总共三天即可，时间拉太长变量反而多，比如线路中途续费或被回收。</p>

<h3>没有第二台机器，能同时跑两组吗？</h3>
<p>答：可以，用两个配置文件同时开窗口即可，但要注意两组会争抢同一条线路的带宽，网络类指标会互相干扰。建议网络类指标分开时段测，隔离类指标可以同时测，因为隔离问题不受带宽影响。</p>

<h3>清 Cookie 和用独立配置文件有区别吗？</h3>
<p>答：有。清 Cookie 只删一小部分存储，localStorage、IndexedDB、Service Worker 缓存、会话恢复记录都还在。独立配置文件是整目录隔离，包括扩展设置和缓存。想彻底干净，删目录比清 Cookie 有效。</p>

<h3>C 组延迟变高，能不能优化回来？</h3>
<p>答：先看虚拟机网络模式，NAT 通常比桥接多一跳；再把虚拟网卡队列和 CPU 分配调高，避免虚拟交换机成为瓶颈。如果优化后仍明显高于宿主机，说明这台机器的资源不够，放弃 C 组、回到 B 组更实际。</p>
